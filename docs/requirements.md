# email и требования продукта

Сверка с документацией продукта
([AI-Incident-Investigation-Platform/docs](https://github.com/AI-Incident-Investigation-Platform/docs)),
`contracts/AUTH_BOUNDARY.md` и 12 §1.

Статусы: **есть** — реализовано; **частично**; **нет** — не начато;
**расходится** — сделано иначе, причина рядом.

| Требование | Статус | Комментарий |
|---|---|---|
| Письмо с кодом входа отправляет сервис `email`, задачу ставит `auth` через RabbitMQ | есть | шаблон `auth.login_code` |
| Письма регистрации, смены почты и приглашения в проект | есть | шаблоны `auth.register_code`, `auth.email_change_*`, `auth.email_changed`, `projects.invitation` |
| Код не попадает в логи | есть | `params` не логируются |
| Повтор задачи не даёт второго письма | есть | `Idempotency-Key` у Resend |
| Просроченное письмо не отправляется | есть | `expires_at` и TTL сообщения |
| Письмо стоит квоты провайдера — не тратить её зря | есть | квоты Resend соблюдаются воркером; письмо со старым кодом снимается новым (`collapse_key`) |
| Приглашение в проект по email | нет | ждёт сервиса проектов |
| Журнал доставки и администрирование писем | частично | логи и метрики; таблицы и админки нет |
